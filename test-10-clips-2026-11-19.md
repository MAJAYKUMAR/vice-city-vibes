## Honest verdict — are these 10 actually good moments?

- **As engineering: 10/10 work.** Scout → hype → cut → check →
  export → Garage, all 10 PASS, no failed cuts.
- **As viral moments: ~4/10 are genuinely good, ~6/10 are weak.**
  The engine scores loudness + hype words in the *transcript*.
  This 12-min stretch of CaseOh is mostly slow story dialogue
  (talking to NPCs, fixing a roof, looking at a snake) — no crash,
  no chase, no big fail. So the "best" moments are chat-reaction
  lines ("chill out chat", "did Jason cheat"), not visual payoffs.
  The tool cannot invent a payoff that isn't in the footage.
  On a high-action 12 minutes (crash / police chase / heist) the
  same scoring would find much better moments.
- **False positives:** 1 of 10 is a content problem (clip 10,
  shower nudity). 0 of 10 are technical failures.
- **Biggest real-world blocker found:** live recording. YouTube
  bot-gates yt-dlp without a login, and Twitch HLS URLs expire
  mid-record. For a real product, live capture needs yt-dlp's own
  live downloader (which refreshes the playlist) or Streamlink —
  not a raw ffmpeg pull of a one-shot URL.

## Stack audit — reuse vs custom (Ajay's point: use existing repos)

### Already in use (proven repos, not our code)

| Part | Repo | How we use it |
|---|---|---|
| Stream/trend discovery | **Bodila51/gtavi-claudecode** (MIT) | `streams.py`, `trends.py`, `moments.py`, `cut.py`, `check.py` |
| Download / live & VOD | **yt-dlp** | VOD sections, live URLs, format selection |
| Transcription | **faster-whisper** (Systran, CTranslate2) | tiny model, word timestamps, ~60 s / 12 min |
| Encoding / captions burn | **FFmpeg** | all cuts, loudnorm -14 LUFS, libass captions, 16:9 |
| Scene detection | **PySceneDetect** (Breakthrough) | installed 0.7.3, tested (see below) |
| Silence removal | **Auto-Editor** (WyattBlue) | installed 29.3.1, tested (see below) |

### Tested in this run (new stack Ajay shared)

- **PySceneDetect — USE, but on a proxy.** Full-res 720p60 detection
  ran 6+ min with no output (CPU-bound frame decode). Killed it.
  On a 640-wide / 15 fps proxy: **16 scenes in a 2-min excerpt,
  detection in ~5 s.** Verdict: adopt it, always on a downscaled
  proxy, to snap candidate boundaries to real scene cuts.
- **Auto-Editor — USE, small gain.** clip_9: 20.80 s → 20.17 s
  (0.63 s silence removed) in 32 s. The clips are already tight,
  so the gain is small — worth it as a final polish step, not as a
  core stage.
- **WhisperX — NOT adopted (yet).** Needs PyTorch (~800 MB+ CPU
  wheel) + alignment models; no torch on this VM. Its win is
  word-alignment + diarization, not speed — and faster-whisper tiny
  already transcribes 12 min in ~59 s on CPU. Revisit only if we
  need speaker labels or tighter word timing than faster-whisper
  gives. Do NOT install it just for speed; it isn't faster here.
- **Remotion — NOT adopted.** JS/Node programmatic rendering would
  replace FFmpeg libass caption burning with a browser render step.
  Our captions already burn correctly via FFmpeg. Remotion adds a
  whole Node toolchain for no quality gain on this pipeline.
  Revisit only if we want animated/motion caption templates that
  libass can't do.

### Better long-term bases found (web search, 2026-11-19)

- **mutonby/openshorts** (MIT, 7,627 stars) — the open-source
  OpusClip alternative. Same pipeline we built piecemeal:
  faster-whisper + PySceneDetect + Gemini moment scoring +
  face-tracked 9:16 reframe + burned captions + MCP/REST API.
  **This is the repo to evaluate as the next base instead of
  gluing our own pieces** — it already does the face tracking and
  per-scene layout our blur layout doesn't.
- **shasshhaank/ClipIt** — Claude skill + local clipper, Whisper
  large-v3-turbo, PySceneDetect shots + motion score, silence
  trimming, word-by-word captions. Smaller, closer to our current
  approach; good reference for the moments lexicon.

### Still custom (ours, no repo does this for us)

- `dashboard.py` / `autopilot.py` / `garage.py` — the glue:
  ranking, watchlist, 50-clip cap, Garage index/HTML.
- `clip.py` — the wrapper: scout → hype stars → cut → export,
  portrait-source fix, `CLIPPER_WHISPER_MODEL` switch.
- `ssl_fix.py` — the VM egress-proxy cert workaround for yt-dlp
  and Hugging Face downloads.
- The Vice City Vibes rules themselves (Rule 2/11, Rule 9b visual
  realism check, AI-label handling) — no repo enforces those.

## Verdict: does the engine actually work on real streams?

**Yes, as a clipper — with three honest limits:**

1. It cuts reliably (10/10 PASS) and the captions/hooks render.
2. Moment quality depends entirely on the footage — on slow
   story dialogue it finds talky moments, not visual payoffs.
   It needs a content filter (clip 10) and ideally scene-aware
   boundaries (PySceneDetect on proxy) before it can be trusted
   unattended.
3. Live capture is the weakest link — YouTube bot-gates, Twitch
   HLS URLs expire. VOD download works fine and is the reliable
   path today.

**Next steps if Ajay wants to go further:** (a) evaluate OpenShorts
as the base (face tracking + Gemini scoring beats our
loudness/lexicon scoring); (b) add a content filter + PySceneDetect
proxy boundaries to `clip.py`; (c) fix live capture with yt-dlp's
live downloader or Streamlink; (d) only then talk about a product /
payment — the tool is test-grade, not sell-grade, today.
